# 单通道模型输入、训练与 FPGA 几何

## 当前平台契约

当前代码只接受单通道 YOLO pose 模型：

```text
模型输入: [1,1,1280,1280] / NCHW / FP16
passthrough: 灰度/HWC1 原强度；三通道取 R，不执行 BGR2GRAY
color_to_gray: 彩图执行 OpenCV BGR2GRAY
共同步骤: resize -> /255 -> NCHW1
```

平台不会把 `[1,1,1280,1280]` 自动补成三通道。第一层卷积必须是 `in_channels=1`；旧 `[1,3,1280,1280]` 权重不能直接交给当前任务。

## 训练改造

重新训练时需要同时改模型、数据加载和增广：

1. 第一层卷积由 3 通道改为 1 通道。
2. Dataset 在增广前后都保持单通道；色彩类增广应删除或改为灰度等价操作。
3. 归一化、resize/letterbox、padding 值和量化/FPGA 保持一致。
4. 有成熟 R-only 三通道权重时，优先迁移除第一层卷积外的权重；第一层可取 R 通道权重或按方案初始化，再微调。不要仅用小数据从零训练作为生产模型。
5. 导出后验证 PT 与 FP16 ONNX 逐样本输出和指标，再做量化。

`20260909_gray1_21c_1680` 约 1200 张、每类约 50 张，只是集成检查点；从零训练 50 epoch 有明显过拟合。当前 PT 测试 F1 约 0.34，低于历史 R-only 全量模型，不能作为生产精度基线。

## 尚未对齐的几何

当前训练/软件主要是原图长边缩放到 1280 并 letterbox；目标 FPGA 路径描述为：

```text
2000x2000 12-bit 灰度
-> 映射到 8-bit
-> 2x2 均值降采样到 1000x1000
-> 四周各补 140 个像素
-> 1280x1280 单通道
```

两条路径不等价。训练、标定、PT 评测、ONNX 评测和 FPGA 实机必须选择同一几何；否则即使通道数一致也会产生尺度、坐标和像素分布偏差。当前软件测包能生成单通道 12-bit 数据，不代表上述 2000→1000→padding 语义已经端到端对齐。

## 验收顺序

```text
源图统计/标签检查
-> 单通道训练与 PT 指标
-> FP16 ONNX 输入 shape/type 与 PT 等价
-> 量化 ONNX 指标
-> PNG/BIN/side-view 回环指标
-> 逐层 BIN 与合并哈希
-> FPGA 实机输出和坐标回映射
```

`Step14 ONNX F1=0` 或当前单通道 ONNX F1=0 都应先作为评测/导出链问题定位，不能只凭结果断言模型没有检测能力；需要比较同一预处理张量、输出 shape、数值范围和 NMS 输入。

## 关键风险

- `passthrough` 对三通道文件取 OpenCV channel 2（R）；输入若不是约定的 R-only，会丢失其他颜色信息。
- `color_to_gray` 会改变 R-only 强度，不能与 passthrough 混用做回归。
- 训练数据过少、类别不均衡或增广仍按彩色设计，会显著降低精度。
- 输入从 3 通道变 1 通道不仅影响第一层，也会改变 ONNX 图和 FPGA 逐层导出脚本的假设。
