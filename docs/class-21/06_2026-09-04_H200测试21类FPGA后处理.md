# H200 测试 21 类 FPGA 后处理程序说明

> 日期：2026-09-04  
> 相关程序：
> - Linux/H200 测试版：`postprocess/fpga_nms/nms_from_output21.c`
> - Zynq 裸板版：`postprocess/zynq_nms/nms_output21_zynq.c`
> - Zynq 头文件：`postprocess/zynq_nms/nms_output21_zynq.h`

---

## 1. 这版程序解决什么问题

历史 2 类后处理只适配：

```text
output0 = [1, 12, 34000]
12 = 4 bbox + 2 class + 6 keypoint
```

最新 21 类模型需要适配：

```text
output0 = [1, 31, 34000]
31 = 4 bbox + 21 class + 6 keypoint
```

FPGA 输出仍按 32 通道对齐：

```text
[34000][32] fp16
```

有效通道是前 31 个：

```text
ch0..3    = bbox: cx, cy, w, h
ch4..24   = 21 类 class score
ch25..30  = keypoint，共 6 通道
ch31      = padding，必须忽略
```

---

## 2. 21 类后处理流程

```text
34000 候选
-> 每个候选取 21 类中最高 score 和 class_id
-> score 阈值过滤，默认 0.25
-> bbox 从 cx,cy,w,h 转为 x1,y1,x2,y2
-> 普通 class-aware NMS，默认 IoU 0.70
-> 业务过滤：20 个地标最多保留最高分的 1 个，月亮可单独保留
-> 坐标还原：x/y 减去 140 padding，并 clamp 到 0..1000
-> 输出最终结果
```

默认类别假设：

```text
class 0..19 = 地球地标
class 20    = 月亮
```

如果实际类别表里月亮不是 20，需要修改：

```c
#define MOON_CLASS_ID 20
```

或在 Zynq 版调用时设置：

```c
params.moon_class_id = <实际月亮类别 ID>;
```

## 4. 用真实 FPGA OUTPUT.BIN 测试

如果已有 FPGA 真实输出：

```bash
./postprocess/fpga_nms/nms_from_output21 /path/to/OUTPUT.BIN
```

程序期望输入大小至少：

```text
34000 * 32 * 2 = 2,176,000 bytes
```

其中：

```text
34000 = 候选数
32    = FPGA 对齐后的通道数
2     = fp16 每个值 2 bytes
```

输出会打印：

```text
candidates after score filter
detections after ordinary NMS
final detections after business filter
```

最终最多输出 2 个结果：

```text
最多 1 个地标
最多 1 个月亮
```

## 5. 没有真实 OUTPUT.BIN 时的冒烟测试

H200 上没有 FPGA 实机时，可以先生成一个假的 `OUTPUT.BIN`，验证程序流程、NMS 和业务过滤是否工作。

生成 mock bin：

```bash
cd /data3/ywang/quantitize-platform
python3 - <<'PY'
import numpy as np
from pathlib import Path

NUM_BOXES = 34000
RAW_CH = 32
out = np.zeros((NUM_BOXES, RAW_CH), dtype=np.float16)

# 候选 0：地标 class 3，高分
out[0, 0:4] = [640, 640, 200, 200]     # cx,cy,w,h
out[0, 4 + 3] = 0.90
out[0, 25:31] = [630, 630, 0.9, 650, 650, 0.9]

# 候选 1：同一个地标附近重叠框，会被 NMS 压掉
out[1, 0:4] = [645, 645, 205, 205]
out[1, 4 + 3] = 0.80
out[1, 25:31] = [635, 635, 0.8, 655, 655, 0.8]

# 候选 2：另一个地标 class 7，不重叠；普通 NMS 会保留，但业务过滤会丢弃
out[2, 0:4] = [300, 300, 120, 120]
out[2, 4 + 7] = 0.70
out[2, 25:31] = [290, 290, 0.7, 310, 310, 0.7]

# 候选 3：月亮 class 20，可与一个地标共存
out[3, 0:4] = [900, 260, 100, 100]
out[3, 4 + 20] = 0.85
out[3, 25:31] = [890, 250, 0.85, 910, 270, 0.85]

p = Path('/tmp/mock_output21.bin')
out.tofile(p)
print(p, p.stat().st_size)
PY
```

运行：

```bash
./postprocess/fpga_nms/nms_from_output21 /tmp/mock_output21.bin
```

预期结果：

```text
candidates after score filter: 4
detections after ordinary NMS: 3
final detections after business filter: 2
```

含义：

1. 4 个候选都超过 score 阈值。
2. 候选 0 和候选 1 是同类别且高度重叠，普通 NMS 后只保留一个。
3. 候选 2 是另一个地标，普通 NMS 会保留。
4. 业务过滤发现有两个地标，只保留最高分地标 class 3。
5. 月亮 class 20 单独保留。

## 6. Zynq 裸板版怎么接入

把这两个文件加入 Zynq 工程：

```text
postprocess/zynq_nms/nms_output21_zynq.h
postprocess/zynq_nms/nms_output21_zynq.c
```

调用示例：

```c
#include "nms_output21_zynq.h"

void run_postprocess(const uint16_t *fpga_output_buffer)
{
    NMS21Params params;
    NMS21Output output;

    nms21_default_params(&params);

    params.conf_thres = 0.25f;
    params.iou_thres = 0.70f;
    params.moon_class_id = 20;
    params.pad_x = 140.0f;
    params.pad_y = 140.0f;
    params.valid_w = 1000.0f;
    params.valid_h = 1000.0f;

    int ret = nms_from_output21_zynq(fpga_output_buffer, &params, &output);
    if (ret != 0) {
        /* handle error */
        return;
    }

    for (int i = 0; i < output.num_detections; i++) {
        NMS21Detection *d = &output.detections[i];
        /*
         * d->class_id
         * d->score
         * d->x1, d->y1, d->x2, d->y2
         * d->kpt[0..5]
         */
    }
}
```

注意：

1. `fpga_output_buffer` 必须指向 `[34000][32] fp16` 输出。
2. 第 32 个通道是 padding，程序不会读取。
3. Zynq 版不做文件 I/O，不读 `OUTPUT.BIN` 文件；它直接处理 FPGA 输出内存。
4. Zynq 版使用静态数组作为工作区，BSS 大约需要数 MB，需要确认裸板工程 linker script 的 DDR/OCM 放置策略。
5. 如果 FPGA 输出 buffer 在 DMA 后由 CPU 读取，需要在调用前做好 cache invalidate。

## 7. 和历史 2 类后处理的差异

| 项 | 历史 2 类 | 最新 21 类 |
|---|---:|---:|
| `NC` | 2 | 21 |
| 有效输出通道 | 12 | 31 |
| FPGA 对齐通道 | 32 | 32 |
| class 通道 | `ch4..5` | `ch4..24` |
| keypoint 起点 | `ch6` | `ch25` |
| padding 通道 | `ch12..31` | `ch31` |
| NMS | 普通 class-aware NMS | 普通 class-aware NMS + 业务过滤 |
| 最终输出 | 最多 `MAX_DET` 个 | 最多 1 个地标 + 1 个月亮 |

---

## 8. 当前限制

1. 这版程序假设 FPGA 已经完成 bbox/keypoint decode，输出的是 `cx,cy,w,h + class + keypoint`，和历史 `nms_from_output2.c` 一致。
2. 这版程序没有把结果写 JSON，只打印文本；如果要接入自动评测，可以后续加 JSON 输出。
3. `MOON_CLASS_ID=20` 是当前假设，需要和训练数据类别表确认。
4. 真实 FPGA 输出如果不是 `[34000][32] fp16`，需要先调整读取布局。
